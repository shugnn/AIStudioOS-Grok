# AIStudioOS-Grok 产品介绍

**版本说明：** 与仓库 `main` 同步的工程说明（2026-11-07）  
**定位：** 人类创始人监督下的 **自治 AI 工作室控制与执行系统**（Grok 独立轨道）  
**并行轨道：** [AIStudioOS-ChatGPT](https://github.com/shugnn/AIStudioOS-ChatGPT)（代码隔离、目标可比）

---

## 1. 一句话是什么

AIStudioOS-Grok 不是某一个垂直 App，而是一套让 **多个 AI / 脚本角色** 在 **预算、权限、验收** 约束下，完成「规划 → 分配 → 执行 → 验证 → 恢复 → 迭代」的 **工作室操作系统雏形**。

人类负责：定目标、重大授权、最终验收。  
系统负责：在授权范围内持续推进，并留下可审计证据。

---

## 2. 要解决什么问题

| 痛点 | 本产品的对应能力 |
|------|------------------|
| Agent 聊天说完就算 | 任务状态机 + 独立验收，禁止口头「做完了」 |
| 越权调网、乱推代码、乱花钱 | 默认拒绝的权限门 + 硬预算 |
| 跑挂了不知道 | 锁、急停、恢复演练、墙钟有界浸泡证据 |
| 单兵脚本冒充「团队」 | 多角色职责拆分（经理 / 工人 / 验收方分离） |
| 双轨无法对比 | 与 ChatGPT 轨统一 P0 目标、GitHub 留痕 |

---

## 3. 核心能力（当前已实现的）

### 3.1 控制平面（Control Plane）

- 目标（Goal）与任务（Task）队列  
- 状态：提议 → 批准 → 执行 → 待验收 → 通过 / 拒绝 / 取消  
- **硬预算**：超支可阻断  
- **硬权限**：如默认拒绝随意联网、git 推送等  
- 检查点与简单恢复  

经理角色 **只提议，不自己说了算**；通过与否走验收路径。

### 3.2 L1 执行层（本机唤醒）

- 跨平台文件锁（Windows / Linux）  
- 可被操作系统定时唤醒跑一轮  
- 急停文件：放置后应安全退出  
- 与控制平面驱动的实验闭环配合  

### 3.3 诚实计量与监督

- 区分「进程成功」与「有业务产出的周期」  
- 墙钟硬截止（避免只靠周期数字冒充时长）  
- 监督层黄/红规则与注入演练（防止「盯梢的人先坏了」）  

### 3.4 业务实验方向（进行中）

**Exp-05 多角色美股研究实验室**：免费数据 → 整理分析 → 短/中线观察池与策略草案（**研究用，非实盘、非投资建议**）。  
开网采集须创始人授权（你已批准「仅免费源」方向；实装前先完成本说明）。

## 4. 明确不是什么

| 不是 | 说明 |
|------|------|
| 已验收的生产级 7×24 运维系统 | 文档与 Issue 均标注 **NOT ACCEPTED** |
| 自动炒股机器人 | 禁止自动下单；池与策略仅为研究草案 |
| 付费数据中台 | 默认零新增付费 |
| 可替代人类的最终决策者 | 创始人保留目标与重大授权 |

---

## 5. 谁适合用

- 需要 **可审计 Agent 团队** 的创始人 / 技术负责人  
- 接受 **本机优先、GitHub 留痕、先证据后宣传** 的协作方式  
- 双轨对比研发（Grok 轨 vs ChatGPT 轨）  

---

## 6. 成功长什么样（产品级，而非单次脚本）

1. 复杂目标能拆成多角色任务并留下状态轨迹  
2. 越权与超预算会被代码拦住，而不是靠自觉  
3. 故障可急停、可恢复，时长与有效产出可分开报告  
4. 业务产物（报告、池子、代码）可复算、可拒收重来  
5. 人类能在 GitHub 上复核证据，而不是只听聊天总结
