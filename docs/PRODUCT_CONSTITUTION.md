## 0. 产品定位（必须写入的能力目标）

AIStudioOS-Grok 是 **模型无关的 AI 工作室操作系统**。定位上 **必须包含** 下列能力（未实现则记「目标态 / 未具备」，禁止写成已完工）：

| 能力 | 定义（验收用语） |
|------|------------------|
| **可插拔** | 指挥中枢与工人/验收等角色后端可配置替换；不绑定单一大模型厂商；人类可关闭或更换适配器后系统仍可在降级模式下运行 |
| **自己拆活并实现改动** | 在授权内，Manager 将目标拆成任务；Worker 能修改仓库内代码/配置或调用工具以完成任务，而不是只跑外部事先写死的唯一脚本 |
| **独立验收驱动** | Verifier 与 Worker 分离；拒绝必须能触发修订再提交；通过/拒绝进入状态机与证据，而不能由执行方自说自话 |
| **自我迭代** | 在授权与预算内，能基于失败/差距发起下一轮「拆活 → 实现 → 验收」，形成可重复闭环；主路径不依赖某一聊天窗口里的轨道员代写 |

**人类直操：** 完工后人类仅凭本机文档中的启动、授权、急停与状态查看即可操控；聊天 AI 退居可插拔部件。

**初衷：** 人类给目标、资源、授权 → 多角色闭环推进 → 证据验收。

## 1. 初衷（不变）

人类给出 **目标、资源、授权** → 系统内多角色在权限与预算下完成：
规划 → 分配 → 执行 → 验证 → 恢复 → 迭代。

有证据、可审计；禁止用口头或聊天总结代替验收。

## 2. 纠偏条款（立即生效）

### 2.1 独立工作系统，不绑定任何一家大模型

- 产品是 **工作室操作系统 / 控制与执行框架**，不是「Grok 专用客户端」。
- 任何 LLM 只能是可插拔的 **指挥中枢** 或 **工人/角色** 或 **工具**。

### 2.2 人类可直接启动与操控

1. 本机命令 / CLI（及未来 UI）可启动、授权、急停、查看状态；
2. 不依赖指定聊天 AI 在线代写；
3. 聊天中的 Grok 等 **退居部件层**，由产品调度。

### 2.3 可插拔 · 拆活实现 · 独立验收 · 自我迭代

四项均为 **产品定位的一部分**，不是可选插件宣传语。

当前工程状态（诚实）：

| 能力 | 状态 |
|------|------|
| 可插拔 | 配置与协议占位已有；任务循环未完全接通 |
| 自己拆活并实现改动 | **未具备** |
| 独立验收驱动 | 状态机与脚本演示有；通用驱动迭代 **未具备** |
| 自我迭代 | **未具备** |

### 2.4 什么不算达成定位

- 对话侧写好业务脚本再 push，宿主只运行；
- 无 Verifier 拒绝→修订路径的「一次跑通」；
- 绑定单一模型才能工作；
- 把脚手架流水线写成「自治 / 自我迭代 PASS」。

### 2.5 脚手架政策

Exp-05 手写 `ingest_live_free.py` / `run_live_pipeline.py` 等 = **scaffold/baseline**，可联调，**不计入**「拆活实现 / 自我迭代」验收。

## 3. 验收总纲（完工时）

1. **模型无关 + 可插拔**：至少两种后端配置可切换；换 LLM 适配器不拆掉控制平面。
2. **人类直操**：仅 USER_GUIDE 流程可完成一次有界目标。
3. **自己拆活并实现**：对指定目标，仓内出现任务分解 + 由 Worker 路径产生的代码/配置变更记录（非仅聊天 commit）。
4. **独立验收驱动**：至少一次 REJECTED → 修订 → ACCEPTED 的完整链，Verifier 身份可区分。
5. **自我迭代**：同一目标下失败后自动或半自动进入下一轮任务，无需轨道员在聊天里重写主逻辑。
6. **硬门**：预算、权限、急停始终有效。

生产级 7×24 另论，默认 NOT ACCEPTED。
