# AIStudioOS-Grok 产品宪章（纠偏 · 创始人 2026-11-07）

本文优先于一切「聊天里把脚本写完算交付」的习惯。

---

## 1. 初衷（不变）

人类给出 **目标、资源、授权** → 系统内多角色在权限与预算下完成：
规划 → 分配 → 执行 → 验证 → 恢复 → 迭代。

有证据、可审计；禁止用口头或聊天总结代替验收。

---

## 2. 纠偏条款（立即生效）

### 2.1 独立工作系统，不绑定任何一家大模型

- 产品是 **工作室操作系统 / 控制与执行框架**，不是「Grok 专用客户端」。
- **不**把某一厂商模型写死为唯一大脑。
- 任何 LLM（Grok、ChatGPT、本地模型、未来其它）只能是：
  - **可插拔的指挥中枢实现**，或
  - **可插拔的工人/角色实现**，
  均可被配置替换、降级、关闭。

### 2.2 人类可直接启动与操控

产品完工验收时必须满足：

1. 人类在本机用 **文档中的命令 / UI / CLI** 即可启动、授权、急停、查看状态；
2. **不依赖** 某个聊天窗口里的「轨道员」在线代写代码；
3. 聊天中的 Grok 或其它 AI **退居部件或工具层**，由产品调度，而不是反过来在聊天里「当工作室本体」。

### 2.3 AI 的位置

| 位置 | 含义 |
|------|------|
| 指挥中枢（可选） | 实现 Manager 接口：拆任务、提议，仍受控制平面硬门约束 |
| 工作角色（可选） | 实现 Worker 接口：写代码、分析、起草，产出进仓库/产物目录 |
| 工具 | 搜索、审查、翻译等一次性能力 |
| **不是** | 产品本身；不是唯一验收人；不是可以绕过预算/权限的超级用户 |

### 2.4 什么不算「工作室自治完成」

- 轨道执行者在对话里写好业务脚本再 `git push`，再让宿主只负责运行；
- 只有确定性脚本工人、没有可替换的「能规划的中枢接口」；
- 文档宣称团队自治，证据却是人工塞进仓的流水线。

上述最多算 **脚手架 / 对照基线**，不得写入「自治业务 PASS」。

### 2.5 脚手架政策

`experiments/exp05-us-equity-lab/ingest_live_free.py`、`run_live_pipeline.py` 等由对话侧写入的采集脚本：

- 标记为 **scaffold / baseline**；
- 可用于联调数据路径；
- **不**证明多角色自治已实现。

目标态：同一业务目标由 **仓内 Manager 提议 + Worker 实现/调用工具 + Verifier 验收** 完成，人类只授权与抽查。

## 3. 验收总纲（完工时）

1. **模型无关**：更换 LLM 适配器后，控制平面与 L1 仍可运行（允许能力变差，不允许整系统绑死）。
2. **人类直操**：仅凭 USER_GUIDE 中的启动/授权/急停流程可完成一次有界任务，无需指定聊天 AI 在线。
3. **可插拔**：至少两个「角色后端」配置槽（例如 `null`/`script` 与 `llm` 占位）可切换。
4. **硬门仍在**：预算、权限、急停、独立验收路径不被 LLM 绕过。
5. **证据**：状态机轨迹 + 产物 + 验收记录在仓库或约定目录，可复核。

生产级 7×24 仍单独验收，默认 **NOT ACCEPTED** 直至另有明示。
